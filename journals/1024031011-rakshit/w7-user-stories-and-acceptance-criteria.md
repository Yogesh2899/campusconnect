# Week 7 - User stories and acceptance criteria

## Problem

Use professor story cards to define observable interface behavior.

## Relevant Context

The story cards made the requirements observable through acceptance criteria tied to individual roles.

## Key Observation

A story can describe a goal without explaining what success looks like on screen. I paired each action with the expected visible response.

## Solution

I worked on stories for scheduling availability, handling meeting requests and proposing new times. I used acceptance criteria that describe visible results, such as a saved slot appearing in the schedule or an approved request showing its updated status. I also considered feedback when a change cannot be saved. The stories established frontend acceptance criteria for the main professor flows.
