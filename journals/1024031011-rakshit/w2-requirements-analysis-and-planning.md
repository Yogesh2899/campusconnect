# Week 2 - Requirements analysis and planning

## Problem

Translate functional requirements into screens, actions and feedback.

## Relevant Context

The selected project needed a clear boundary across account access, faculty availability, appointment requests and updates.

## Key Observation

The proposed feature list included reporting and other extensions. I prioritized the student and professor workflows that support the first version.

## Solution

I mapped student tasks to viewing availability, sending requests and checking status. I mapped professor tasks to maintaining slots and acting on incoming requests. I also identified the need for distinct feedback when a list is empty, a request is pending or a selected slot is unavailable. The requirements provided a screen inventory and priorities for the proposed React frontend.

## Next Steps

Map each screen to the relevant student or professor use case.
