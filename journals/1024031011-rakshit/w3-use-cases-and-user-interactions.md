# Week 3 - Use cases and user interactions

## Problem

Work out the professor-side interactions from the use-case templates.

## Relevant Context

The use-case model identified the Student, Professor and Administrator actors and specified their interactions.

## Key Observation

The same request can appear in different contexts. I used the request status to determine which actions the interface should make available.

## Solution

I focused on professor use cases for editing availability and viewing and processing meeting requests. I mapped each action to its required inputs and expected feedback. For example, changing availability needs a valid time range, and a decision on a request needs a clear status in the request list. The use cases established the inputs, actions and feedback for the professor screens.

## Next Steps

Trace approvals and rescheduling across both interfaces.
