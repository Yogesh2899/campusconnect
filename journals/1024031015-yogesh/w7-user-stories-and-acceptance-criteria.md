# Week 7 - User stories and acceptance criteria

## Problem

Turn acceptance criteria into planned tests with clear expected outcomes.

## Relevant Context

The story cards made the requirements observable through acceptance criteria tied to individual roles.

## Key Observation

Broad acceptance criteria make outcomes hard to judge. I tied each expected result to an actor, starting condition and observable change.

## Solution

I worked on student stories for availability, meeting requests and cancellations. For a valid request, I specified a pending meeting and the expected subsequent status update. For an unavailable slot or a conflicting request, I specified a rejection with no extra booking. For a student attempting a professor-only action, I specified that access should be denied. The story cards provided acceptance checks for the main booking and security scenarios.

## Next Steps

Cross-check the cases against the report and organize the mid-semester materials.
