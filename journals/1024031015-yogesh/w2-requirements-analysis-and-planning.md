# Week 2 - Requirements analysis and planning

## Problem

Identify the highest-priority requirements for functional testing and security review.

## Relevant Context

The selected project needed a clear boundary across account access, faculty availability, appointment requests and updates.

## Key Observation

Some quality requirements described system targets. I kept these as verification targets and based functional checks on observable system behavior.

## Solution

I worked on the problem statement, scope and proposed solution. I grouped verification around account access, professor availability, booking, approvals, cancellation and status updates. For access control, I mapped the expected permissions of students, professors and administrators so that each feature had a clear authorized actor. The requirements had a basis for prioritizing tests and reviewing role boundaries.

## Next Steps

Map permissions and negative scenarios to the detailed use cases.
